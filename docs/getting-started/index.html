Getting started with Tuva

Tuva gives your research a memory and puts an agent that knows your project in the tools you already use. This page explains what it is, which surface to install, and what to do first.

What Tuva is

Tuva is a research assistant that keeps a persistent memory of each of your projects. It reads the files, papers, and notebooks in a project folder, records what you and your coding agents do there, and uses that memory to answer questions, find things, and help you write.

Under the hood, Tuva is a small daemon that runs on your own machine. Everything it learns stays in your project folder. Three surfaces talk to that one daemon, so you can use whichever fits the moment and they all share the same memory:

  • The desktop app. Chat, projects, your knowledge base, research memory, and a daily paper digest.
  • The CLI. The same daemon from a terminal, a server, or an HPC cluster. It also wires Tuva into Claude Code, Codex, and Cursor.
  • The VS Code extension. Tuva inside VS Code or Cursor, next to your notebooks.

Coding agents such as Claude Code, Codex, and Cursor connect to Tuva over MCP. Once connected, they can search your project, read your papers, and recall what happened in earlier sessions without you re-explaining it.

Pick a surface and install it

Most people start with the desktop app. Install the CLI if you work in a terminal or on a cluster, or if you mainly want Tuva for your coding agents. Install the extension if you live in VS Code. You can install more than one; they share the daemon.

  • Desktop app macOS and Windows. The full Tuva experience in one window. Install →
  • Tuva CLI macOS, Linux, Windows, and HPC clusters. Connects your coding agents. Install →
  • VS Code extension VS Code and Cursor. Built for notebooks, papers, and data. Install →

Tuva is in early access. Sign-in works for email addresses on the access list. If you have not met the team yet, join the waitlist or email hello@tuva.ai.

Your first ten minutes

  1. Sign in.

    Enter your email and type the one-time code Tuva sends you. There is no password.

  2. Open a project.

    A project is a folder on your machine. Point Tuva at the folder where your notebooks, scripts, and papers live. Tuva writes its memory into a .entropy folder inside it and never changes your files.

  3. Let it index.

    Tuva reads the project and builds a knowledge base: notebooks, code, PDFs, and notes. On a typical project this takes a minute or two.

  4. Connect your coding agents.

    Turn on Claude Code, Codex, or Cursor in Connected apps (desktop) or with tuva mcp (CLI). Start a new agent session afterwards so it picks up the Tuva tools.

  5. Ask something.

    Open a chat and ask about your project. Tuva answers with citations back to the exact cell, file, or page.

The desktop app

The desktop app lives in your menu bar (macOS) or system tray (Windows). Closing the window hides it; Tuva keeps working in the background.

  • Projects. All your projects in one place. Open one, create a new one, or switch between them.
  • Project home. An overview of the open project: what Tuva has read, what it has learned, and what it is working on.
  • Chats. Conversations with Tuva scoped to the open project, with citations to your own files.
  • Knowledge base. The sources Tuva has read for this project: local files, papers, and anything synced from connected apps.
  • Research memory. A daily record of what happened in the project, built from your chats, your agent sessions, and changes to your files. Browse it by day, or as a graph of connected episodes.
  • Agent sessions. The Claude Code and Codex sessions that ran in this project, so Tuva can learn from them.
  • Digest. New papers that match what you are working on, found by a background run and summarised against your project.
  • Connected apps. Turn Tuva on for Claude Code, Codex, Cursor, and Claude Desktop. Link Notion and Google Drive so their pages become sources.
  • Updates. The app updates itself. A banner appears when a new version is ready.

The CLI

The tuva command is a terminal interface to the same daemon. It is the right choice on a server, in tmux, or on a cluster login or compute node. It is also how the desktop app and the extension connect coding agents under the hood.

CommandWhat it does
tuvaGuided setup the first time. Once set up, shows status.
tuva start / tuva stopBring the daemon up or down. Safe to re-run.
tuva statusDaemon health and which coding agents are wired.
tuva init / tuva indexSet up the current folder as a project and build its knowledge index.
tuva chatChat with Tuva about the current project from the terminal.
tuva memoryInspect the project's memory: state, daily digests, and the episode graph.
tuva mcpTurn Tuva on or off for Claude Code, Codex, Cursor, and Claude Desktop.
tuva launchStart a coding agent session already wired to this project's context.
tuva connectorsLink Notion, Google Drive, and other external sources.
tuva doctorCheck whether this machine or cluster can run Tuva, and what to fix.
tuva feedbackSend a note or a bug report to the Tuva team.

The VS Code extension

The extension puts Tuva in a sidebar next to your notebooks. It is listed on the Marketplace as Rao, the name of Tuva's research agent, and works in VS Code and Cursor.

  • Chat with your project. Ask questions grounded in your notebooks, code, and the PDFs in your workspace. Citations link to the exact cell or page.
  • Work in notebooks. From any cell: Add to Chat, Debug Error, Analyze Figure, or Tag Cell so Tuva keeps it in context.
  • Read papers faster. Index a folder of PDFs and ask across them by name.
  • Writing assistant. Edits in your own voice, drawing on your results and notes, shown as diffs you step through.
  • Skills. Teach Tuva how your project uses a scientific package, so it stops guessing.
  • Agent integrations. One command wires Claude Code and Codex to the same knowledge base.

Coding agents and MCP

Tuva exposes its memory to coding agents through an MCP server called tuva-context. Once an agent is connected it gains tools to search the project, read paper sections, recall past episodes, and get the project's current state. This is how Claude Code can answer "what did we decide about the normalisation step last week" without re-reading everything.

Turn an agent on from Connected apps in the desktop app, from Agent Integrations (MCP) in the extension, or with tuva mcp in a terminal. Then start a new agent session; an existing session will not pick up the tools.

Tuva can also learn from your agent sessions. When you turn that on, past Claude Code and Codex transcripts for a project become part of its memory.

Getting help

Email hello@tuva.ai. From the desktop app, use the feedback button in the account menu. From a terminal, run tuva feedback -m "...".

If something is not working, tuva doctor checks your environment and says what to fix. When you write in, include the output of tuva --version, tuva status, and tuva doctor.
