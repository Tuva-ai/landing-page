Installing the Tuva CLI

The tuva command runs Tuva's daemon from a terminal and connects it to Claude Code, Codex, and Cursor. Let your coding agent install it, or do it by hand in four steps.

What you need

  • macOS, Linux, or Windows. On a cluster, a login node where you can install software.
  • Python 3.10 or newer. We recommend 3.12. Check with python3 --version.
  • Internet access on that machine. The first start downloads Tuva's backend.
  • An email address on the Tuva access list.

Option 1: let your coding agent install it

The fastest route. Open Claude Code, Codex, or Cursor in the folder you work in most and paste this:

Paste into your coding agent 
Install Tuva by following the instructions at https://tuva.ai/docs/skills/tuva-install/SKILL.md

Your agent runs every step for you and asks only for what it cannot detect: your email, which project folders to include, and which agents to connect. It works for a laptop and for a remote cluster reached over SSH. Read the skill to see exactly what it does.

Option 2: install by hand
  1. Install Python 3.12 if you do not have it.

    Check with python3 --version. If it is missing or older than 3.10, install Python 3.12 from python.org, or with your package manager. On a cluster, module load python/3.12.

  2. Install the CLI.
    Terminal 
    python3 -m pip install tuva
tuva --version

    If the shell says tuva: command not found, pip put it in a folder that is not on your PATH yet (usually ~/.local/bin). Open a new terminal, or run python3 -m tuva instead. On Windows use python -m pip install tuva and python -m tuva.

  3. Run the guided setup.

    Change into a project folder and run tuva with no arguments.

    Terminal 
    cd ~/my-project
tuva

    The checklist checks your environment, starts the daemon, signs you in, sets up and indexes this project, offers to learn from your Claude Code and Codex sessions, connects your coding agents, and links external connectors. Each optional step asks first. Finished steps are skipped, so it is safe to re-run.

    The first start provisions a private environment for the backend. On a laptop this takes about a minute. Do not interrupt it.

  4. Start a new agent session.

    Claude Code, Codex, and Cursor load Tuva's tools when they start. Open a fresh session in the project folder.

On an HPC cluster

Tuva runs on login nodes and compute nodes. Two things differ from a laptop:

  • If your cluster provides a module, use it instead of installing: module load tuva. Everything else is the same.
  • On a Slurm cluster, run setup inside an allocation on a compute node (for example srun --pty bash), not on the login node. The daemon scopes its state per node and job.

Run tuva doctor first. It checks scheduler placement, whether your home directory can hold Tuva's database, credential persistence, and network egress, and tells you what to change. The most common fix is pointing state at local scratch when home is on a network filesystem.

The install skill handles all of this over SSH if you would rather let your agent do it.

Signing in

Setup signs you in. To do it separately, or on a machine without a browser:

Terminal 
tuva auth login
tuva auth whoami

Tuva emails you a one-time code. Type it at the prompt. The code is single-use and expires in a few minutes. If it does not arrive, check spam, wait ten minutes before requesting another, and make sure the address is on the access list.

Connecting coding agents

tuva mcp lists the coding agents found on this machine and lets you toggle Tuva for each one. To do it non-interactively:

Terminal 
tuva mcp configure claude     # or codex, cursor, claude-desktop
tuva mcp status

This writes a tuva-context entry into the agent's own config file and leaves everything else there untouched. Run it on the machine where that agent runs. Then start a new agent session.

Troubleshooting
  • tuva: command not found right after installing. Your PATH does not include ~/.local/bin yet. Run export PATH="$HOME/.local/bin:$PATH" and add that line to your shell profile.
  • Python is missing or too old. Tuva needs Python 3.10 or newer. Install 3.12 from python.org or your package manager, or on a cluster module load python/3.12, then install again.
  • The first tuva start seems stuck. It is downloading the backend. Run tuva logs -n 50 in another window to watch progress. Do not start a second one.
  • Sign-in code never arrives. Check spam. Wait ten minutes before requesting another; requesting several at once gets rate-limited. If the address is not on the access list, email hello@tuva.ai.
  • My agent does not see Tuva. Run tuva mcp status. If the agent is listed as wired, start a new agent session; existing sessions do not reload their tools.
  • Upgrading. python3 -m pip install --upgrade tuva, then tuva restart.

Still stuck? Send tuva --version, tuva doctor --json, tuva status --json, and tuva logs -n 200 to hello@tuva.ai with one line about what you were doing.
